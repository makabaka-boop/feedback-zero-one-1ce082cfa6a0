# KV 检查点服务（纯后端、崩溃一致）

仅依赖 **Python 3.11 标准库**，从零实现的持久化 KV 服务。不使用任何数据库或
现成事务引擎，持久化由“数据文件（检查点快照）+ 追加日志”自行实现。

## 1. 目录与运行

```
kvstore/
  framing.py     # 磁盘帧编解码：4 字节小端长度 + UTF-8 JSON + 4 字节小端 CRC32
  engine.py      # 严格 JSON、事务校验、内存状态、追加日志、检查点、崩溃恢复
  server.py      # HTTP 接口（ThreadingHTTPServer + 引擎内全局锁）
runserver.py     # 启动入口
test_framing.py  # 帧层单元测试
acceptance_test.py  # 端到端验收（含三类强退、尾截断/损坏区分、并发）
```

启动（数据目录不存在会自动创建；初始表为空、各源断点为 0、版本为 0）：

```bash
python3 runserver.py --data-dir ./data --host 127.0.0.1 --port 8000
# 端口传 0 由内核分配，实际监听端口打印在首行标准输出
```

数据目录下的文件：

| 文件 | 含义 |
| --- | --- |
| `log` | 追加事务日志，每条事务一帧 |
| `snapshot` | 最近一次检查点的全量状态（行、断点、版本、全部回执），单帧 |
| `snapshot.tmp` / `log.tmp` | 检查点过程中的临时文件，正常结束后不存在 |

## 2. HTTP 接口

### `POST /load` —— 装载事务

请求体严格 JSON：

```json
{
  "txid": "t1",
  "sources": {"alpha": [0, 5], "beta": [0, 2]},
  "ops": [
    {"op": "put", "key": "k1", "value": "v1"},
    {"op": "put", "key": "k2", "value": null},
    {"op": "del", "key": "k1"}
  ]
}
```

- `txid`：非空字符串；`sources`：非空对象，源名是非空 ASCII 字母数字串。
- `[start, end]`：非负有符号 64 位整数，`end >= start`；**整数禁止布尔**
  （`true/false` 一律 400），也不接受浮点。
- 提交前 `start` 必须等于该源当前断点（新源断点为 0）；成功后断点变为 `end`。
- `ops` 为**有序数组**，仅允许 `put`/`del`：
  - `put` 恰好含 `op/key/value`，`value` 为字符串或 `null`，新增或替换；
  - `del` 恰好含 `op/key`，删除不存在的 key 整批拒绝；
  - 空 `ops` 合法。
- key 为非空 ASCII 字母数字串。按 `ops` 顺序求值，任一步非法则**整批拒绝**，
  无任何副作用。
- **未知或重复 JSON 成员一律拒绝**（`object_pairs_hook` 检出重复 key；
  `NaN/Infinity` 亦拒绝）。

成功回执：

```json
{"txid": "t1", "version": 1, "idempotent": false}
```

幂等规则（仅成功事务占用 txid）：

- txid 已占用：**先按 JSON 结构判幂等**，与规范化后的原内容相同则返回原版本、
  `idempotent: true`，**不重新检查断点、不再应用**；内容不同返回 `409`。
- 新 txid：检查全部断点 → 追加并 fsync 日志 → 行、全部断点、回执同时提交、
  版本加一。

### `GET /status` —— 状态查询

```json
{"version": 2, "rows": {"k1": "v1"}, "checkpoints": {"alpha": 5, "beta": 2}}
```

行按 **key 字节序**、断点按**源名字典序**输出；读在锁内取一致拷贝，
永远不会看到半个事务。

### `GET /receipts` —— 全部成功回执

按版本顺序返回；检查点回收日志后回执仍然保留：

```json
{"version": 2, "receipts": [{"txid": "t1", "version": 1}, {"txid": "t2", "version": 2}]}
```

### `POST /checkpoint` —— 检查点

把全量状态（行、断点、版本、全部回执）原子发布为快照并回收此前日志：

```json
{"version": 2, "rows": 1, "checkpoints": 2, "receipts": 2, "reclaimed": true}
```

错误码：语义/结构错误 `400`；txid 冲突 `409`；路由不存在 `404`；
存储损坏 `500`（启动阶段损坏则进程以码 2 拒绝启动）。

## 3. 磁盘格式与崩溃一致性

### 帧格式（日志与快照通用）

```
+--------------------+-------------------+--------------------+
| uint32 长度（小端） |  UTF-8 JSON 载荷  | uint32 CRC32（小端）|
+--------------------+-------------------+--------------------+
```

校验和为 Python 3.11 `zlib.crc32(json 载荷) & 0xffffffff`，**仅覆盖 JSON**。

日志内部字段（自行设计）：

```json
{"type": "txn", "version": 7, "txid": "t1", "request": { ...原始请求... }}
```

### 提交流水线

1. 严格解析与全部语义校验、断点预检、`del` 预检（失败即 400，无副作用）。
2. 编码事务帧，`write` → `flush` → `fsync(log)`。
3. fsync 成功后才在内存同时提交行、全部断点、回执并版本加一。

因此：

- **成功回执在重启后必然保留**（回执对应的记录已 fsync）。
- 未回执事务要么完整生效（fsync 已完成），要么完全不生效（帧未持久化）；
  客户端重试时，若已生效则按幂等返回原版本，与恢复状态一致。

### 恢复规则

- 先加载 `snapshot`（必须恰好一条完整帧，否则拒绝启动）。
- 再顺序重放 `log`：版本号必须连续、重放仍过完整语义校验；快照后重复出现的
  事务按 txid 幂等跳过（检查点切换窗口的正常情况）。
- **末尾不完整记录忽略**，并把日志截断到最后一条完整帧边界。
- **完整记录 CRC 错误必须拒绝启动**，且不修改任何文件、保留现场；
  即使损坏记录之后还跟着半截垃圾，CRC 错误也优先于“尾截断”。

### 检查点发布与日志切换（每步强退都可恢复）

1. 全量状态写 `snapshot.tmp`，文件 fsync、目录 fsync；
2. `os.replace(snapshot.tmp, snapshot)` + 目录 fsync —— **检查点发布点**；
3. 空 `log.tmp` fsync 后 `os.replace` 原子替换旧 `log`，目录 fsync；
4. 重新打开追加句柄。

| 强退位置 | 恢复行为 |
| --- | --- |
| 步骤 1 后、rename 前 | 无快照，tmp 被忽略；照旧重放完整日志 |
| 步骤 2 后、切换前 | 快照已发布；重放日志时其中事务在快照里，幂等跳过 |
| 步骤 3 后 | 快照 + 空日志，状态即检查点状态，继续提交版本接续 |

行、断点、版本、全部回执始终同进退；检查点成功后此前日志被回收，但这些
状态全部保留在快照中。

### 并发

`ThreadingHTTPServer` 多线程接收，引擎内一把 `RLock` 串行化所有提交与检查点，
读操作在锁内取快照拷贝——整体串行等价，读不见半个事务。

## 4. 验收

```bash
python3 -I test_framing.py       # 帧层：小端长度、CRC、截断 vs 损坏
python3 -I acceptance_test.py    # 端到端，约 84 项断言
```

验收覆盖（`acceptance_test.py`）：

- A 功能与严格校验：未知/重复成员、布尔冒充整数、浮点/越界/负数、空 ops、
  del 不存在、整批原子拒绝、幂等返回原版本、异内容 409、字节序/源名排序；
- B 正常重启后状态与全部回执一致、断点接续、旧 txid 仍幂等；
- C **追加处强退**：写半帧 → 尾部截断忽略、txid 未占用；fsync 后崩溃 →
  事务完整生效、重试幂等、回执在；
- D **检查点发布与日志切换三处强退**（tmp 后 / rename 后 / 切换后）均可恢复，
  恢复后检查点可完成、日志回收、版本接续，并再次重启核对；
- E 区分**尾截断**（恢复并截断）与**完整记录 CRC 损坏**（拒绝启动、现场保留、
  CRC 错误优先于尾部垃圾）；
- F 快照完整记录损坏 → 拒绝启动且文件原样保留；
- G 12 线程 × 8 事务并发提交 + 并发检查点 + 并发读：版本 1..N 唯一连续、
  无脏读、全部回执保留，重启后状态一致。

故障注入通过环境变量开启（仅验收用，触发点直接 `os._exit(9)` 硬退）：

| 变量 | 注入点 |
| --- | --- |
| `KV_FAULT_APPEND_AFTER_WRITE` | 事务帧写一半后硬退（确定性制造半帧） |
| `KV_FAULT_APPEND_AFTER_FSYNC` | 日志 fsync 后、返回回执前硬退 |
| `KV_FAULT_CKPT_AFTER_TMP` | 临时快照 fsync 后硬退 |
| `KV_FAULT_CKPT_AFTER_RENAME` | 快照发布后、日志切换前硬退 |
| `KV_FAULT_CKPT_AFTER_SWITCH` | 新日志切换后硬退 |
